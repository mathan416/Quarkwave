## Hands-on acceptance pass, when both boards are available

1. Record board/core and library versions, the three source hashes from the [index](README.md), and the assembled wiring revision.
2. Record the owner-confirmed return-wire level shift, continuity-checked jumper endpoints, and measured Pico RX voltage, then power both boards via their USB ports; check Wi-Fi, `quarkwave.local`, IP fallback, separate **Pico** and **Uno** connection labels, note playback once the audio stage exists, and note release on browser disconnect.
3. Compare browser controls with Uno behavior for each group: envelope, tone, modulation, arpeggiator, delay, chorus, bitcrush, tremolo, drive/fold, and Panic. Log MIDI CC values and compare panel readouts, including vibrato rate and master volume; repeat Randomize and check its full-range effects. Check keyboard velocity 1, 100, and 127 and view switching with a held note.
4. Save and load a user patch, factory preset, factory-to-user copy, and Commit snapshot; restart each board separately and confirm the selected Pico patch is restored on clean Uno startup without opening a browser. Test a lost completion acknowledgment and return-wire disconnection.
5. Exercise DIN notes, bend, CC, and clock without the Pico; then test the Pico RTP gateway with notes, bend, CC, and clock. Confirm standalone activity blocks automatic takeover, while clock alone does not. Check the documented Program Change and SysEx allowlist on each input, including malformed messages and standalone status. Check that BLE is absent in this build.
6. Update the guides with verified results, then remove resolved entries from this queue or link them to development issues.
